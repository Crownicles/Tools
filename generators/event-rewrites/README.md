# Réécriture des big events

Before / after viewer for the rewritten big events of Crownicles. For each event it shows the original and the rewrite side by side: introduction, choice labels and outcomes. Each outcome shows its text, its conditions and its consequences (health, money, time, karma, status effect, item, destination…).

Open `index.html` directly (no server needed). Link to an event with its id: `index.html#56`.

The **Source** switch at the top of the sidebar picks where the data comes from:

- **Atelier**: the rewrite workshop bundled in `data.js` (see *Data* below), with the agents' notes and the `validate.py` output.
- **Branches GitHub**: any two branches of `Crownicles/Crownicles`, loaded from GitHub in the browser (`github.js`). "Avant" is the base branch, read at the point where the compared branch left it (like a pull request, so commits added to the base since then don't show up as reverted); "Après" is the compared branch. Only the events whose texts (`Lang/fr/events.json`) or mechanics (`Core/resources/events/<id>.json`) differ are listed, unless "Inclure les events identiques" is checked. Changed outcomes and intros get a "modifiée" badge. The comparison is shareable: `index.html?base=develop&head=outcomerequirements#30`.
  - Place names, city menus and event icons are read from the "Après" branch. Neighbours load in the background.
  - Each comparison uses 5 GitHub API calls (the merge base and folder listings), plus 2 for the branch list (cached 10 min). Unauthenticated, GitHub allows 60 calls per hour. Files come from `raw.githubusercontent.com`, which is not counted.
  - There is no canon block, agent note or validation in this mode.

## Features

- By default only the texts are shown: introduction, then for each choice its label and its outcomes, each with a short condition tag and one line of consequences. Outcomes keep their ids in the rewrites, so before/after outcomes with the same id sit on the same row. Added outcomes and choices get a small "nouvelle" badge.
- Everything else is folded, with a one-line summary: the place context (game description, neighbours and travel times, city menu, triggers, AI model, full canon block), the agent notes and the `validate.py` output.
- The sidebar lists the events with their status (rewritten / in progress / validator errors), outcome counts before → after and the share of conditional outcomes.
- **Profil de joueur** (sidebar, folded): set level, karma, stats, class, pet, cooking level, a full or empty material bag, the upgrade level and enchantment of the weapon and armor to grey out the rewritten outcomes this player cannot get. Possible outcomes show their odds (the game picks uniformly among them). The profile is saved in `localStorage`.
- Below 1000 px the before/after columns are interleaved in a single column.

## Data

```bash
python3 build.py [--src <rewrite dir>] [--lang <Crownicles/Lang/fr>] [--out data.js]
```

`--src` is the rewrite working folder (defaults to `src/`). It also holds the brief given to the writers (`brief.md`, `reference.md`). It holds:

| Path | Content |
|---|---|
| `input/<id>.json` | Context and original version of an event: place, neighbours, city menu, canon block, triggers, original texts and mechanics, and optionally a contributor's `draft`. Generated by `prepare.py <Crownicles dir> <id> [--draft-ref <commit>]` |
| `draft-rework.md` | Brief for reworking a contributor's draft |
| `out/<id>.json` | The rewrite: texts, `data` (mechanics and `requirements`), `icons`, `notes`. Events without one are shown as "en cours". |
| `pets.json`, `classes.json` | Names used to display pet and class conditions |
| `validate.py` | Run for each rewrite; its errors and warnings are embedded |

`--lang` (defaults to `../../../Crownicles/Lang/fr`) is only used to show French names for inns, meals, rooms, shops and services. Without it, ids are shown.

Re-run `build.py` whenever a rewrite changes.
